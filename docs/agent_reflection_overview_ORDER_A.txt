一、整体定位
- 本项目由「前端（Django）」与「后端（Reverie 仿真服务器）」组成。
- 后端以 ReverieServer 为核心，驱动多名 Persona（即智能体/Agent）在地图世界中持续感知、计划、行动，并通过文件与前端松耦合交互。
- Persona 的核心认知链：Perceive（感知）→ Retrieve（检索）→ Plan（计划）→ Reflect（反思）→ Execute（执行）。

二、Agent（Persona）的组成
1) 记忆子系统
  - 空间记忆（SpatialMemory / MemoryTree）
    • 结构：world → sector → arena → [game_object...]
    • 用途：用于“在哪里能做什么”，影响行动地址选择与对象选择。
  - 联想/长期记忆（AssociativeMemory）
    • 定义：人物的长期知识流，持久化保存 event / thought / chat 等“内容节点”。
    • 结构：ConceptNode（event / thought / chat），常见字段：embedding_key、poignancy、keywords、created/expiration、last_accessed、S-P-O（可选）。
    • 作用：被 Retrieve/Plan/Converse/Reflect 召回与复用；高价值结论以 thought 形式沉淀，支持可解释（证据链）。
    • 访问：按“最近性×重要性×相关性”融合排序召回；被访问时刷新 last_accessed。
    • 索引：关键词倒排、文本→向量缓存（embedding_key→vector）、时间序列与过期策略。
  - 短期/工作记忆（Scratch）
    • 定义：当下上下文与“工作台”，保存此刻的目标/状态/缓冲区/超参，不做长期持久化。
    • 感知与注意：vision_r、att_bandwidth、retention（控制可见范围、带宽、去重窗口）。
    • 世界与日程：curr_time、curr_tile、daily_req、f_daily_schedule、f_daily_schedule_hourly_org。
    • 当前行为：act_address、act_duration、act_description、act_event、act_pronunciatio。
    • 路径与进度：planned_path、act_path_set。
    • 对话：chatting_with、chat、chatting_with_buffer、chatting_end_time。
    • 反思与检索权重：importance_trigger_max / importance_trigger_curr / importance_ele_n；recency_w / relevance_w / importance_w；recency_decay。
  - 二者区别与转变（生成一个表格）
    | 维度 | AssociativeMemory（长期） | Scratch（短期/工作台） | 说明/影响 |
    | --- | --- | --- | --- |
    | 存续 | 持久化、可追溯 | 瞬时，随步进/阶段切换更新或清空 | 决定是否作为“长期知识”被反复复用 |
    | 粒度 | 存“节点”（event/thought/chat） | 存“状态/指针/缓冲”（当前目标/上下文） | 前者面向知识，后者面向执行上下文 |
    | 写入入口 | Perceive/Converse/Reflect 将内容写回 | 记录产生写入所需的临时状态/参数 | 反映“内容产出”与“过程管理”的分工 |
    | 使用路径 | Plan/Converse/Retrieve 召回作为依据 | 注入临时上下文以驱动当前一步 | 检索→注入→执行 的流水线 |
    | 升华路径 | Reflect 抽象多证据为 thought 写回（含证据链/S-P-O/poignancy/向量） | 提供当次反思所需的焦点/权重等临时条件 | 让“碎片→结论化知识”沉淀入长期库 |
    | 清理/衰减 | 受时间衰减与过期策略影响 | 回合/阶段重置，避免陈旧状态干扰 | 控制规模与新鲜度 |

2) 认知模块
  - 感知（perceive）：视野内空间写入空间记忆；同一 arena 内收集事件，按距离选前 att_bandwidth 个；对过去 retention 去重；为新增事件写入长期记忆（event + 可选 chat 关联），并按事件 poignancy 递减触发器值（importance_trigger_curr）与累加元素计数（importance_ele_n）。
  - 检索（retrieve/new_retrieve）：
    • retrieve：按关键词索引取相关 events/thoughts。
    • new_retrieve：基于 recency（最近性）、relevance（嵌入相似度）、importance（poignancy）综合打分，返回 Top-N 关键节点（并刷新 last_accessed）。
  - 计划（plan）：
    • 长期：当日首次或跨天触发，生成 wake_up_hour、broad-strokes daily_req 与分钟级 hourly_schedule（必要时在日内进行任务分解）。
    • 短期：选定 sector/arena 与 game_object（可回退 <random>），生成动作三元、表情、物件动作等，写入 Scratch 的当前行动。
    • 对话/反应：基于检索与策略决定是否交互、等待或继续。
  - 反思（reflect）：详见后文「三、反思-检索-洞察 全链路」。
  - 执行（execute）：寻路到目标地址候选 tile（尽量避开他人占位），输出下一步移动坐标与描述。

三、反思-检索-洞察：从“事件”到“智慧”的全链路
（面向概念与运行机理的说明，不包含源码细节）

0) 核心术语与作用（对齐业务语言）
| 概念 | 通俗解释 | 作用 |
| 触发器（Trigger） | 类似“反思闹钟”，达到阈值后启动反思流程。 | 控制反思频率，避免资源浪费。 |
| 焦点（Focal Points） | 从近期记忆中筛选出的主题（如“与 Alice 的旅行对话”）。 | 聚焦反思方向，避免无目标处理海量记忆。 |
| 检索（Retrieval） | 围绕焦点从记忆库中“找证据”（多条事件/想法/对话节点）。 | 为生成洞察提供素材，确保结论有依据。 |
| 洞察（Insights） | 基于多条证据提炼的高阶结论（如“Alice 偏好徒步”）。 | 把碎片化信息升华为可复用知识。 |
| 证据（Evidence） | 支撑洞察的具体记忆节点（node_id 列表）。 | 确保结论可追溯、可审计。 |
| 三元（S, P, O） | 将洞察转为“主语-谓语-宾语”结构。 | 为记忆提供结构化标签，便于快速索引。 |
| 重要性分数（Poignancy） | 记忆/洞察的重要性/情感强度打分。 | 决定优先级，影响检索权重与触发器扣减。 |
| 向量表示（Embedding） | 将文本转成语义向量。 | 支持相似性检索与主题聚合。 |(以上生成一个表格)
- 触发器（Trigger）
  - 做什么：像“积分表”，记录今天发生的有分量的事；分量越大，积分扣得越快。
  - 何时用：感知到新事件时扣分；分扣完（≤0）就触发一次反思；反思后重置。
  - 为什么：避免每条小事都反思，攒到“值得总结”再统一提炼。
- 焦点（Focal Points）
  - 做什么：把“最近若干条重要记忆”的文本压缩为3±个主题切口（如“旅行偏好”）。
  - 何时用：反思启动后第一步；决定检索方向，避免漫无目的翻库。
  - 为什么：主题先行能大幅减少无关干扰，提升检索精准度与成本效率。
- 检索（Retrieval）
  - 做什么：围绕每个焦点从长期记忆里“找证据”。
  - 怎么选：同时看“最近性（越新越好）/重要性（分高优先）/语义相关性（越像越好）”。
  - 副作用：被选中的证据会“刷新最近访问时间”（越用越活跃）。
- 洞察（Insights）
  - 做什么：把多条证据拼成高阶结论（可复用的“知识”）。
  - 附带：必须给出依赖哪些证据（索引→node_id），保证可追溯、可解释。
- 证据（Evidence）
  - 做什么：为洞察背书的“原文档”。来源可为事件、聊天、过往思考。
  - 为什么：防止“无依据的猜测”进库；也方便复盘与审计。
- 三元（S, P, O）
  - 做什么：把一句话的结论结构化成“主语-谓语-宾语”的标签。
1) 阶段1：触发判断（是否需要反思？）
- 条件：importance_trigger_curr ≤ 0，且联想记忆中存在事件或想法。
- 机制：每观测一个“非 idle”事件，会：
  • 计算该事件的 poignancy；
  • importance_trigger_curr -= poignancy；
  • importance_ele_n += 1；
  当累计扣减达阈值，触发反思。
- 失败回退：若无可用材料（例如当日全是空闲），本轮跳过，等待后续积累。
- 目的：用“事件的重要性”驱动反思频率，节约资源。

2) 阶段2：筛选焦点（该关注什么？）
- 输入：最近 importance_ele_n 个关键节点的 embedding_key 文本。
- 行为：通过语言模型生成若干 Focal Points（3±）。
- 输出：焦点列表（如“Alice 的旅行偏好”“户外装备兴趣”）。
- 价值：把注意力集中到“最近最重要”的主题。
 - 质量要求：焦点应明确、短句化、指向性强（如“户外徒步偏好”）。

3) 阶段3：检索证据（有哪些相关记忆？）
- 对每个 Focal Point 进行 new_retrieve：
  • 候选集：去掉“idle/空闲”后，取所有事件与思考；
  • 取所有（非 idle）event + thought，按 last_accessed 排序；
  • 计算三项分：
    - Recency：根据 recency_decay 衰减的最近性；
    - Importance：节点自身的 poignancy；
    - Relevance：焦点文本与节点 embedding 的余弦相似度；
  • 归一化并按权重（recency_w / relevance_w / importance_w，与内置 gw 加权）组合，取 Top-N；
  • 更新这些节点的 last_accessed（被使用即“温习”）。
- 结果：为每个焦点得到一组“证据节点”。
 - 直观理解：像“把最近且重要、而且跟主题最像”的放在前面。

4) 阶段4：生成洞察与证据（结论是什么？依据是什么？）
- 目标：用证据集合写出“可落地”的高阶结论（非复述，需有信息增量）；
- 约束：每条洞察必须明确指向一组证据索引，杜绝“空口断言”；
- 结果：得到若干条“结论→证据索引列表”的映射。
- 输入：证据节点列表（带 embedding_key 文本）。
- 行为：语言模型基于证据生成多条“洞察 thought”，并为每条洞察给出“证据下标列表”。
- 映射：将证据下标映射为真实 node_id，形成洞察→证据 node_id 的映射。
- 价值：洞察可追溯到具体记忆节点，避免“无中生有”。

5) 阶段5：结构化处理（如何让机器理解？）
- 三元（S, P, O）：把洞察转为语义三元组（如“[Alice, 喜欢, 徒步]”）。
- 重要性分数（Poignancy）：为洞察打分，决定“知识地位”。
- 向量（Embedding）：为洞察文本生成 embedding（便于后续相似性检索与召回）。
- 时间属性：记录 created 与 expiration（如有效 30 天）。

6) 阶段6：写回记忆（如何保存成果？）
- 将洞察作为 thought（“思考”）节点写入人物的长期记忆，并完成以下动作：
  • 文本（content）：保存洞察的完整自然语言表述。
    - 作用：作为人读与机读的统一语义源；同时是后续生成更高层结论时的原始材料。
  • 三元（S, P, O）：把洞察抽象为“谁-做了/是什么-什么”的结构。
    - 作用：提供结构化索引点，便于快速筛选（例如按主语或谓语聚类）。
  • 证据（filling = [node_id ...]）：记录支撑该洞察的具体记忆条目编号。
    - 作用：保证可追溯、可审计；在需要解释来源或回滚时直接定位到原始事件/对话。
  • 重要性（poignancy）：对洞察本身的重要性/情感强度打分。
    - 作用：影响后续检索排序与反思触发的扣减力度（高分更“显眼”）。
  • 向量（embedding_key → vector）：为洞察文本生成并缓存语义向量。
    - 作用：支持“语义相关性”检索；相同文本避免重复计算，降低成本。
  • 时间标注（created/expiration）：记录创建时间与有效期（如 30 天）。
    - 作用：与“最近性”打分协同，形成时间衰减；到期内容可降权或清理。
  • 加入序列与索引（seq_thought / 倒排表 / 缓存）：
    - 序列：按时间把该节点加入“思考序列”，成为可被遍历的长期记忆流的一部分。
    - 倒排表：按关键词将该节点纳入关键词→节点表，支持关键词直达检索。
    - 嵌入缓存：向量缓存在人物侧的嵌入集合中，供后续复用。

  下游会如何使用这些写入结果：
  • 计划（Plan）：在长/短期计划生成时，直接引用这些洞察作为“高层知识”，减少对原始碎片的反复处理；
  • 对话（Converse）：在构建对话上下文与关系总结时，被检索为“认知背景”，提升对话连贯性；
  • 检索（Retrieve）：在“最近性-相关性-重要性”融合排序中，这些 thought 作为候选与事件共同被评估；
  • 反思（Reflect）：后续反思的焦点生成也会把它们作为“近期重要项”，促进知识的再抽象。

  一致性与质量控制建议：
  • 证据链必须可解引用（node_id 有效）；
  • 避免把“无依据的假设”写成洞察；
  • 同义重复可通过向量近邻与关键词合并策略去重或合并。

  示例（抽象化场景）：
  • 文本：“Alice 喜欢高强度徒步与高海拔路线。”
  • 三元：[Alice, 喜欢, 高强度徒步]
  • 证据：[node_82（聊天：‘上周爬黄山’）、node_95（分享登山鞋链接）]
  • 重要性：8.5（较高）
  • 向量：embedding_key = “Alice 喜欢高强度徒步与高海拔路线。” → vector
  • 后续：当系统需要给 Alice 推荐活动或在对话中提及偏好时，优先召回该 thought 作为“高层依据”。
  
 - 价值：不仅把“结论化知识”沉淀入长期记忆，还同步完成索引、缓存与证据绑定，使其能被计划/对话/检索稳定复用并可解释。

7) 阶段7：重置触发器与特殊流程
- 重置：importance_trigger_curr 置回 importance_trigger_max，importance_ele_n 清零，等待下一轮积累。
- 对话后反思（特殊）：当对话到达结束时间：
  • 生成“规划性思考”（Planning Thought）：如“明天推荐 Alice 户外装备商店”；
  • 生成“备忘 Memo”：如“Alice 喜欢高海拔路线”；
  • 两者均写入 thought，并用最近 chat 节点作为 evidence。

十、端到端流程：从行动到交流、记忆、反思与应用（串联视图）
- 世界推进与初始选择
   • 世界时钟按步推进；每步评估“当前小时主题”和“分钟级动作”。
   • Agent 基于计划、位置、可达场景与他人分布，选择下一动作（移动/观察/互动/独处）。

 - 感知（Perceive）
   • 在场景内读取视野半径内的对象、人物、事件。
   • 对“非空闲”事件计算重要性；去重同类噪声；必要时写入长期记忆（文本、时间、重要性、向量等）。
   • 触发器按事件重要性扣减，为后续反思做累积。

 - 是否选择交流（Converse 的触发）
   • 条件：空间接近、双方状态允许、社交概率命中或计划指向交流。
   • 意图：由短期计划与上下文决定（如结识/求助/推进任务）。

 - 交流与信息获取
   • 对话前：检索双方的偏好、历史、关系摘要，构建对话上下文。
   • 对话中：生成 utterances；识别新信息（观点、偏好、计划、事实）。
   • 对话后：聊天作为事件入库；触发“对话后专项反思”，写入 Planning 与 Memo。

 - 信息处理与入库（Associative Memory）
   • 事件/聊天择优入库：过滤空闲、去重、评分重要性、生成向量、更新倒排与时间序列。
   • 私有向量缓存：命中则复用，未命中再生成，控制成本。

 - 反思何时进行（Reflect 触发）
   • 常规：触发器≤0 且近期有可用材料时启动。
   • 专项：对话结束立刻追加一轮“规划/备忘”反思。

 - 反思做什么（焦点→检索→洞察→写回）
   • 焦点：从近期高价值内容中凝练 3± 个主题切口。
   • 检索：按“最近性×重要性×相关性”融合排序选出证据。
   • 洞察：基于证据生成结论，标注证据索引；结构化为 S-P-O、打分重要性、生成向量、标注时间。
   • 写回：以 thought 节点入库，绑定证据链，更新序列、倒排与嵌入缓存。

 - 反思后改变什么（对行为与计划的作用）
   • 计划：长/短期计划优先召回 thought 作为高层依据（如“偏好徒步→建议相关活动”）。
   • 对话：关系与偏好被稳定引用，对话更连贯、减少重复询问。
   • 触发器：重置为上限，等待新一轮积累；常被使用的节点因“最近性”更新而更易被再次召回。

 - 知识库如何嵌入（Embedding 与存储）
   • 每个 Agent 维护私有“文本→向量”缓存，与长期记忆节点一一呼应。
   • 任何入库文本（事件/聊天/思考）可生成向量用于相似度检索；命中缓存避免重复生成。

 - 人物如何调用知识库（检索与使用逻辑）
   • 检索：给定查询（焦点/对话上下文/计划子目标），按融合评分召回事件与 thought。
   • 使用优先级：若存在覆盖度高的 thought（结论型知识），优先使用其文本与三元，减少对原始碎片的反复加工。
   • 可解释性：需要解释时，沿 thought 的证据链回溯到原始节点，说明“依据何在”。

 - 小例子（一分钟走查）
   • 早上在市场遇到 Alice（感知：记录“遇见 Alice”，重要性中等）。
   • 发起交谈（交流）：得知她周末计划徒步；对话入库，触发专项反思。
   • 专项反思：生成 Memo“周末徒步”与 Planning“推荐装备店”。
   • 当晚常规反思：围绕“旅行偏好”焦点，检索近几次对话，产出洞察“偏好高强度徒步”，写回 thought（含证据链、SPO、向量、重要性）。
   • 次日计划：规划环节优先召回该 thought→行动建议与对话更贴合她的偏好。

十一、检索融合打分（直观版）
 - 目标：给每条候选记忆一个“可解释”的综合分，选出 Top-N 作为证据。
 - 评分维度：
   • 最近性（Recency）：越新越高，按时间衰减（recency_decay）。
   • 重要性（Importance/Poignancy）：节点自带分，越关键越高。
   • 相关性（Relevance）：焦点文本与节点向量的语义相似度（余弦）。
 - 归一与加权：
   • 各分先归一化到相同区间；
   • 融合：Score = wr·Recency + wi·Importance + ws·Relevance（支持内置 gw 调整）。
 - Top-N 与阈值：
   • 推荐 N=5~15；如分布过平，可叠加最小阈值，剔除低于阈的噪声；
   • 被选中节点刷新 last_accessed，形成“用则新”的记忆活跃度。
 - 默认权重建议（起步）：
   • wr=0.25，wi=0.35，ws=0.40（主题导向场景可把 ws 调到 0.5）；
 - 调参策略：
   • 强主题任务→提高 ws；强经验依赖→提高 wi；关注即时上下文→提高 wr；
   • 当天多轮反思→适当提升 wr 抑制旧信息；知识稀疏→提升 wi 强化关键少量节点。
 - 质量与监控：
   • 关注命中率（被 Plan/Converse 采纳的比例）、解释率、平均检索成本与时延。

十二、对话后专项反思（Planning / Memo）
 - 触发规则：
   • 对话结束即触发一次专项反思（不等待触发器清零）；
   • 可选门槛：对话时长/轮数≥阈值，或抽取到的“有效信息量”≥阈值。
 - 产出物：
   • Planning：下一步可执行建议（做什么/何时/在哪里/与谁）。
   • Memo：可复用要点（偏好、禁忌、约束、关键事实）。
 - 入库与索引：
   • 作为 thought 入库，绑定最近 chat 节点为证据；
   • 生成 S-P-O、重要性、向量、时间，更新倒排与嵌入缓存；
   • 标记为“对话后生成”，便于区分来源与后续统计。
 - 与常规反思的关系：
   • 专项反思偏“快收敛、强行动”；常规反思偏“主题级总结与抽象”；
   • 二者互补：专项产出可在当日晚间常规反思中被再次引用与升华。
 - 下游影响：
   • 近期计划优先召回 Planning；
   • 对话上下文优先召回 Memo，减少重复询问与寒暄；
   • 高频被用的条目因最近性刷新而更易再次进入检索前列。
 - 质量控制：
   • 必须有证据链（chat 节点）；禁止“空口断言”；
   • 设立同义合并窗口（向量近邻+关键词）避免冗余膨胀。
 - 监控指标：
   • 建议被采纳率、重复问句降低率、转化为具体行动的比例、平均写回延迟。

四、对 Agent 行为的影响
1) 更低推理成本
- 未来在计划与对话中，可以直接以“洞察 thought”作为高阶知识，不必反复扫描底层碎片，降低 LLM 调用与检索代价。

2) 行为更连贯
- 长期计划与短期分解可利用历史洞察，让人物表现出“持续的偏好与目标”，减少随机性与割裂感。

3) 可解释性与可审计
- 每条洞察附带证据 node_id，可追溯到具体的事件或对话，便于复盘与安全审计。

五、模块协作关系（简要）
- 记忆管理（AssociativeMemory / Scratch / SpatialMemory）：
  • 提供近期事件/想法；保存新洞察；维护 embeddings 与倒排索引。
- 检索器（new_retrieve）：
  • 输入焦点文本；按最近性/相关性/重要性融合输出证据集合。
- 语言模型（LLM）：
  • 生成焦点、洞察、三元、重要性评分；在计划与对话中产出语义内容。
- Embedding 服务：
  • 将文本转为向量（支持相似度计算与复用）。

六、典型场景
- 日常反思：一天中多次事件导致触发器归零 → 生成“Bob 关注环保”“Charlie 周末露营”等洞察。
- 对话后专项反思：与 Alice 的商务对话结束 → 自动写入 Planning 与 Memo 两类 thought。

七、注意事项（工程向）
- 阈值调优：importance_trigger_max 过高会导致反思短缺，过低会频繁反思浪费资源。
- 证据优先与可追溯：任何洞察必须能映射到 node_id 列表，避免“虚假记忆”。
- 嵌入复用：优先命中人物私有 embeddings.json，未命中再计算，降低成本。
- 计划/对话的 LLM 依赖：洞察质量受 prompt/模型质量影响，必要时做缓存或模板化。

八、文件/目录要点（只列关键抽象）
- 后端：reverie/backend_server/
  • reverie.py（仿真主循环）
  • persona/persona.py（Agent 汇总与 move()）
  • persona/memory_structures/{spatial_memory.py, associative_memory.py, scratch.py}
- 前端：environment/frontend_server/
  • storage/<sim_code>/ 下是仿真现场数据与每名人物的私有长期记忆（含 embeddings）。

A. 术语扩写（更直白的理解与使用位置）
- 触发器（Trigger）
  - 做什么：像“积分表”，记录今天发生的有分量的事；分量越大，积分扣得越快。
  - 何时用：感知到新事件时扣分；分扣完（≤0）就触发一次反思；反思后重置。
  - 为什么：避免每条小事都反思，攒到“值得总结”再统一提炼。
- 焦点（Focal Points）
  - 做什么：把“最近若干条重要记忆”的文本压缩为3±个主题切口（如“旅行偏好”）。
  - 何时用：反思启动后第一步；决定检索方向，避免漫无目的翻库。
  - 为什么：主题先行能大幅减少无关干扰，提升检索精准度与成本效率。
- 检索（Retrieval）
  - 做什么：围绕每个焦点从长期记忆里“找证据”。
  - 怎么选：同时看“最近性（越新越好）/重要性（分高优先）/语义相关性（越像越好）”。
  - 副作用：被选中的证据会“刷新最近访问时间”（越用越活跃）。
- 洞察（Insights）
  - 做什么：把多条证据拼成高阶结论（可复用的“知识”）。
  - 附带：必须给出依赖哪些证据（索引→node_id），保证可追溯、可解释。
- 证据（Evidence）
  - 做什么：为洞察背书的“原文档”。来源可为事件、聊天、过往思考。
  - 为什么：防止“无依据的猜测”进库；也方便复盘与审计。
- 三元（S, P, O）
  - 做什么：把一句话的结论结构化成“主语-谓语-宾语”的标签。
  - 为什么：机器快速定位与聚合（如“所有‘喜欢-徒步’的人”）。
- 重要性分数（Poignancy）
  - 做什么：衡量每条内容的“分量/情绪强度”。
  - 为什么：影响检索排序，也决定触发器扣分力度（越重要越快触发反思）。
- 向量表示（Embedding）
  - 做什么：把文本放到“语义坐标系”，近义实质接近。
  - 为什么：支持“按意思”查找，而不是只能靠关键词。

C. 世界时间 × 行为映射（直观时序）
- 时间粒度：系统以固定步长推进世界时间（如每步=数秒现实时间）。
- 日程视角：
  - 小时级：今天的“主题安排”（睡眠、工作、用餐等）；
  - 分钟级：对“当前小时主题”进行细化（分解为一连串短动作）。
- 执行视角：
  - 找地点：根据空间记忆选择合适场景与对象；
  - 走路径：在地图上找最短路并逐步前进；
  - 占位规避：尽量避免多人挤到同一个单元格。
- 越日：日期跨越触发“重新做当天长程计划”，并在必要时修订身份/状态描述。

D. 阈值与权重建议（调参指北）
- 触发器上限：建议与平均事件重要性×预期事件数同量级（避免过密/过稀）。
- 最近性衰减：0.95~0.995 常用区间；越接近1越“记仇”。
- 三评分权重：若希望更“跟主题走”，加大相关性权重；若强调“重大事件”，加大重要性权重。
- 注意带宽/保留窗口：带宽大更敏感，窗口长更去重；二者要配合，避免“既漏看又重复”。

E. 知识库嵌入（面向应用的说明）
- 角色私有：每个角色有自己的“文本→向量”缓存集合，互不干扰；
- 来源多元：事件/思考/聊天/日程总结都会入库并向量化；
- 命中优先：遇到相同文本优先命中本地缓存，未命中再生成，控成本；
- 复用场景：检索（相似度）、关系总结、对话主题保持、长期偏好识别。

F. 角色分层（专家组 / 平民组）操作化建议
- 专家组：
  - 更高反思频率与更强“重要性/相关性”权重；
  - 产出“公共洞察”，供群体复用；
  - 关注规划型结论（建议/指导），并在对话中以此进行传播与校正。
- 平民组：
  - 更高的互动概率与注意带宽；
  - 更多事件与聊天入库，推动舆论扩散；
  - 对专家组洞察产生响应（采纳/讨论/转述）。
- 安全与解释：所有洞察必须绑定证据，防止“无依据扩散”。

G. 工程注意（落地可行性）
- 反思频度：以触发器控制为主，必要时加“每日最少/最多”保护；
- 去重策略：近义洞察可做向量近邻合并，避免知识重复膨胀；
- 资源控制：向量生成/检索可做缓存，长尾文本延迟计算；
- 观测指标：
   - 洞察命中率（被计划/对话检索到的比例）
   - 可解释率（具有效证据链的比例）
   - 反思效率（每次反思消耗 vs. 行为改进收益）。
